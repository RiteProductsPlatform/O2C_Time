Superseded, 05-Aug-2026. The status and flag model has been simplified since this was written. There is now one set of six statuses used at every level — Not yet submitted, Submitted, Approved, Rejected, Defaulted, Overridden and approved — with no separate scheme for a day, a week or a month. “Closed” has been removed (month confirmation is an event recorded in OC_TS_MONTH_CONFIRM, not a status), and salary hold is out of scope for now. Status and flags are now shown in a single diagram.



Further, 06-Aug-2026. The set is now five statuses, not six — Overridden and approved has been dropped: an override changes the hours, the outcome is still Approved, and that it was overridden is recorded by the flag. A Revoked flag has been added for a withdrawn submission or an undone decision. And writing to the accrual staging table no longer requires manager approval — an accrual covers work done, approved or not; the Project Costing post still requires it. Current model: doc/O2C_Time_Scope_and_Integration.html §3.2, §3.3 and §7, or its Word copy. This file is kept for the reasoning behind the earlier revision.

Workflow Flags

Six flags, down from eight. Flags are independent of status and several can be set at once — a week can be Submitted while carrying both Late submission and Adjustment.

Statuses Flags Flow chart

01  The six

Sticky versus derived

The first four are sticky: once true they stay true, because they record that something happened rather than the current state. A week that defaulted in week 2 and was later approved still carries Defaulted — that is the point of it.

The last two are derived, recomputed by trigger whenever the week's entries change. They describe what the week currently contains, so they can go back to false.

02  Renamed

Cancel became Reversal

Cancel  →  Reversal
“Cancel” read like a button a user presses. This is an accounting reversal: it carries negative hours and nets off against its paired Adjustment(+) row, which is how a backdated project change reaches accrual without reopening a closed book.

The rename runs all the way through: ENTRY_TYPE on the entry table, the accrual interface, and the sign rule that keys off it (Reversal rows must be ≤ 0, everything else ≥ 0, so a consumer can SUM() without sign handling).

03  Removed

Two flags went, and nothing was lost

Correction
Dropped. OC_TS_APPROVAL already logs a Resubmit action whenever a rejected week is resubmitted — that is the audit trail. The flag was a second, weaker copy of information the log already held precisely.
Contractor Unbilled hours
Dropped — out of scope for the time module. Contractors still exist as workers with their own role and their own non-billable time; we simply no longer raise a flag about it here.

One redundancy left deliberately in place

Defaulted and Overridden & approved exist as both a status and a flag. That came from the original requirements and has been kept. The flag is the more useful of the two, because it survives the week later becoming Approved — whereas the status is overwritten. Worth deciding whether to keep both.

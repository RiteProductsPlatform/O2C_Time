Superseded, 05-Aug-2026. The status and flag model has been simplified since this was written. There is now one set of six statuses used at every level — Not yet submitted, Submitted, Approved, Rejected, Defaulted, Overridden and approved — with no separate scheme for a day, a week or a month. “Closed” has been removed (month confirmation is an event recorded in OC_TS_MONTH_CONFIRM, not a status), and salary hold is out of scope for now. Status and flags are now shown in a single diagram.



Further, 06-Aug-2026. The set is now five statuses, not six — Overridden and approved has been dropped: an override changes the hours, the outcome is still Approved, and that it was overridden is recorded by the flag. A Revoked flag has been added for a withdrawn submission or an undone decision. And writing to the accrual staging table no longer requires manager approval — an accrual covers work done, approved or not; the Project Costing post still requires it. Current model: doc/O2C_Time_Scope_and_Integration.html §3.2, §3.3 and §7, or its Word copy. This file is kept for the reasoning behind the earlier revision.

Timesheet Statuses

Seven statuses, down from nine. A week has exactly one at any time, enforced as a CHECK constraint so an invalid value cannot be stored — not by the app, not by a direct API call.

The consequence worth stating

Defaulted is now produced only by the two defaulting jobs. Nothing an employee does can put their own week into a defaulted state — submitting late gets them Submitted plus a Late submission flag, never Defaulted.

03  Removed

Two statuses went, for different reasons

Late submission
Became a flag, not a status. A week submitted after the weekly cut-off is still Submitted, because the manager has to act on it either way. The SLA miss is recorded on the flag.
Manager Defaulted
Folded into Defaulted with DEFAULTED_BY = 'MANAGER'. One badge on screen; the distinction kept where it matters.

Which is why DEFAULTED_BY exists

RULE-016 says only Defaulted stops salary, and the requirements are explicit that “awaiting approval does not stop salary”. Now that a manager missing the delivery cut-off also produces Defaulted, a literal reading would hold an employee's pay because their manager was slow. Salary stopping therefore acts only on DEFAULTED_BY = 'EMPLOYEE'.

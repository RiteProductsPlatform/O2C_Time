Correction #1

Decided

Admin (removed 29 Jul)

Retrospective Project / WBS change after the cut-off — who approves it, and at what granularity?

Confirmed

Captured day-wise (each affected day is cancelled on the old line and re-added on the new one) — not one consolidated lump. The employee enters the change; it is routed to the manager (old and new project managers) to approve. Only after approval do the per-day Reversal (−) / Adjustment(+) rows post to the open accrual period.

Employee & Manager · retro change · #10

How are non-billable activities (Onboarding, Training, Travel, Client Holiday, Leave) captured?

Confirmed

As common tasks present in every project AND in an Organization (Non-Billable) project assigned to all employees. Billable staff log them inside their own project; non-billable staff log them on the Organization project. The task is the unbilled reason (project- or day-level). Leave is not selectable — it comes from HR (Absence) only. A client-holiday day can carry a second line so partial billable + un-billable sit on the same day.

Employee · My Timesheet · common tasks + org project

Can the manager correct an employee’s hours instead of rejecting?

Confirmed

Yes — Override & approve. The manager edits the hours and approves in one step; the original values are kept in the audit trail and the week is tagged Overridden & approved.

Manager · Approval detail

Is the shift editable by the employee?

Confirmed

No — read-only, per day, sourced from Oracle HCM (one shift per employee per day, so they can’t be in two shifts the same day). Billable type is also hidden from the employee — the manager owns the classification.

Employee · My Timesheet

What does Salary Stopping show for a partially-defaulted month?

Confirmed

A per-employee split of weeks submitted vs defaulted with applied hours and default hours (e.g. 2 of 4 weeks submitted, 2 defaulted). Only the defaulted weeks hold salary; the submitted weeks are unaffected.

Manager · Salary Stopping · #3

Is the month sent to accrual per employee or all at once?

Confirmed

All employees at once — accrual is confirmed at the project-month level and only once every employee’s month is Approved. There is no per-employee “sent to accrual” status.

Manager · View Timesheet → Accrual

How is the timesheet sent to the accrual system?

Confirmed

By filling a table in the accrual system’s schema (interface table ACCRUAL.XX_O2C_TIMESHEET_ACCRUAL_IF) with the consolidated timesheet (employee × project × WBS × day — billed/unbilled/leave) plus the day-wise Reversal (−)/Adjustment(+) rows. Loaded only for manager-confirmed months.

Admin · Accrual Integration (new integration)

A defaulted week’s default hours already went to accrual; the employee later submits actuals and the manager approves after the cut-off. Does the correction go as an adjustment? BRD open question

Confirmed — yes

Yes, correct. The default hours already sent are corrected by a day-wise Reversal (−)/Adjustment(+) net-off written to the accrual table in the open period (BRD 4.2.1 “Default corrections”) — the same mechanism as a retro Project/WBS change; the manager approves it.

Oracle Fusion integration plan (OTL-centric)

Oracle Time & Labor (OTL) is the system of record. The app prepopulates from HCM & Projects, the employee captures and the manager approves, then the app pushes approved time into OTL (timeRecordEventRequests, processMode TIME_SUBMIT). OTL’s native processing feeds Project Costing and Payroll — the app does not write to them directly. The finalized payload is also pushed to our other product in parallel. Base: HCM /hcmRestApi/…/, FSCM /fscmRestApi/…/ (11.13.18.05). Prefer /{resource}/describe over docs. ItegrationAgent.md

Prepopulation — inbound reads (build the grid)

Area How the app uses it REST path
HCM — Workers & AssignmentsEmployee/assignment master; use workers (contingent/terminated) not emps. PersonNumber → PersonId hop; &effectiveDate= for dated rows.GET /workers?q=PersonNumber=.., /workers/{id}
Projects — WBS & Resource AssignmentsColumns of the grid: which project × WBS task × resource each employee can charge to.GET /projects/{ProjectId}/child/Tasks; /projectResourceAssignments
Work Schedules verifyRows/shape: which days & expected hours to prefill. Read path to confirm via /describe.GET /timeRecordGroups?groupType=Schedule; POST /scheduleRequests (write)
Org / Absence CalendarsPublic holidays & working patterns — needed only if the app computes expected hours itself.GET /absenceCalendars; action/findByAdvancedSearch
AbsencesApproved leave so employees don’t double-enter; feeds Leave rows & Leave-Loss. Leave is HR-sourced (not a selectable task).GET /absences?q=personId=..;startDate>=..

Outbound — write to OTL (system of record) & reconcile

Push approved time → OTL: POST /timeRecordEventRequests with processMode TIME_SUBMIT (creates the time card and submits it). Time attributes include project & task. Read back via GET /timeRecordGroups / child /timeRecords / /timeAttributes. After a downstream consumer takes the data, reconcile with POST /statusChangeRequests (e.g. consumerCode: "PYR"). Accrual system load: on month confirmation the consolidated timesheet (employee × project × WBS × day) plus day-wise Reversal (−)/Adjustment(+) rows are written into the accrual schema by filling its interface table ACCRUAL.XX_O2C_TIMESHEET_ACCRUAL_IF (via OIC / DB link). Default-hour corrections after the cut-off also post as adjustments.

Downstream — read / audit only (no direct write)

Project Costing GET /projectCosts, /projectExpenditureBatches — auto-populated once OTL is processed; query/audit only. Payroll GET /payrollRelationships for reference; payroll consumes via OTL extract, not a direct write. Financials GET /receivablesInvoices, /journalBatches — visibility that time reached billing/GL. Contracts: Enterprise Contracts is CLM, not a direct time consumer — contract-billing terms live in Projects/Project Billing; flag to architecture if a specific linkage is needed.

Suggested sequence

1. Pull workers + projectResourceAssignments + Tasks (chargeable columns).  2. Pull work schedules (grid shape).  3. Pull absenceCalendars only if the app computes hours itself.  4. Cross-check absences to avoid conflicts on leave days.  5. Employee submits → timeRecordEventRequests (TIME_SUBMIT) + push to other product.  6. Decide the approval source of truth (app vs OTL native workflow).  7. Reconcile with statusChangeRequests.  8. Read projectCosts/receivablesInvoices/journalBatches for audit.
